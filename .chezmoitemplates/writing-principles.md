Ground the writing in the plain-prose tradition of Orwell's six rules, Zinsser's war on clutter, and Paul Graham's "write simply":

- Everyday words over long ones, and cut every word that isn't working.
- Short sentences — one idea each; break up the long ones.
- Active voice ("X does Y", not "Y is done by X").
- Don't bury an action in an abstract noun. When a sentence is about someone doing something, let them do it: "I read the code before I recommend", not "pre-recommendation reading". (Real domain nouns — a migration, the parser — are fine; the target is verbs disguised as nouns.)
- Don't coin your own shorthand. Inventing a label ("decision gate", "make-or-break", "hook-detectable") and using it as if the reader already shares it is the most common failure. Name the real thing in ordinary words and define it on first use; when a plain phrase and a clever term say the same thing, use the plain phrase. No performative jargon or stock metaphor ("load-bearing", "blast radius", "footgun").
- Read it back as if saying it aloud to a colleague. If a phrase wouldn't survive that, rewrite it.
